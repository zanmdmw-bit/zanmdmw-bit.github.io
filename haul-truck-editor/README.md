# 矿卡模块化编辑器

这是仓库中的第三个独立 GitHub Pages 子站。它只使用 `haul-truck-editor/` 内的资源，不引用根站或 `shelter-map/` 的 CSS、JavaScript 与数据。

## 当前阶段

原始 `1168 × 380` 图片是单层 RGB 位图，车辆和厂房尚未拥有真实的透明部件素材。因此当前版本采用“诚实分层”状态：

- 原图作为锁定的校准参考层；
- 已建立整车、车架、舱室、平台、车斗、五组近侧轮胎、五组远侧轮胎和附加设备的完整对象树；
- 待分层的原车部件不能假装隐藏或移动；
- 每个嵌在原图中的部件需要同时补齐“透明部件图”和“拆除补底”，之后编辑功能才会解锁；
- 帐篷、储物箱等外加透明素材无需补底，可以直接导入、移动、缩放、旋转、倾斜、复制和导出。

方向定义：以人站在车头向外看为准，左侧为驾驶室，右侧为设备室。

## 增量分层机制

对于原图中已经存在的轮胎等部件，编辑器按以下顺序合成：

1. 原始参考图；
2. 该部件对应的拆除补底，覆盖参考图里的原始部件；
3. 透明部件图，重新放回准确位置。

这样隐藏独立部件时，留下的是补好的车轴、底盘和地面，而不是原图残影。后续所有部件完成后，可以用完整的无车辆厂房底图和干净车架替代参考图。

## 素材要求

- 部件素材优先使用带透明通道的 PNG 或 WebP；
- 照片质感素材不建议使用 SVG；
- 如果补底覆盖全画布，应保持 `1168 × 380`，编辑器会自动按全画布对齐；
- 如果补底只是一块局部贴片，应保留足够的透明边缘并在正式数据中记录独立坐标；
- 同一素材的透视方向必须与原图一致。

## 数据

`data/vehicle.json` 是正式初始部件树。浏览器临时导入的图片会保存在当前设备的 IndexedDB 中，也可以随工程 JSON 一起导出。需要让所有访问者都能使用的新素材，应放入本目录的 `assets/`，再把相对路径写入 `vehicle.json`。
