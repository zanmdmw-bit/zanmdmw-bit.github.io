# 避难所 RP 地图网页

这是与仓库现有双陆世界网页完全隔离的独立页面。当前页面以广州市天河公园的卫星影像为底图，在真实经纬度上显示立体混凝土防御围墙，并对围墙沿线的地基、清理带、维护道路、排水、门区和湖岸进行局部地表重建。

## 必须了解的底图限制

Esri World Imagery 是第三方栅格瓦片，页面不能也没有修改、删除瓦片里的树木、水面、草地或建筑像素。工程走廊使用不透明的 WGS-84 GeoJSON 多边形覆盖冲突区域，再在其上叠加地基、碎石、压实土、道路、岸坡和结构细节。覆盖层固定在真实地理坐标上，会随地图平移、缩放、旋转和倾斜同步变化。

这种方式能在施工范围内遮住大部分原树冠和地表，但拍摄影像中越过走廊边缘的大树冠、建筑阴影或倾斜影像仍可能在过渡区外露。那是原始影像内容，并不代表真正完成了影像级“移树”。

## 地图与三维技术

- 地图库：MapLibre GL JS 5.21.1，保留 WebGL 1 回退。
- 三维渲染：MapLibre `fill-extrusion`，高度和基础高度按米配置。
- 地表重建：MapLibre GeoJSON `fill` 与低高度 `fill-extrusion`。
- 卫星底图：Esri World Imagery 栅格瓦片。
- API Key：当前公开端点不需要密钥。若服务政策变化，只能使用供应商允许浏览器调用的受限密钥，不能向公开仓库提交私密密钥。
- 署名：右下角保留 MapLibre、Esri 及影像数据提供方署名。
- 缩放：限制为 14—19 级；不承诺超过数据源原生分辨率后继续变清晰。

Esri 服务及署名说明：

- <https://www.arcgis.com/home/item.html?id=10df2279f9684e4a9f6a7f08febac2a9>
- <https://developers.arcgis.com/documentation/esri-and-data-attribution/interactive-maps/>

## 坐标、范围与米制计算

- 配置坐标：WGS-84 `[纬度, 经度]`。
- GeoJSON 坐标：WGS-84 `[经度, 纬度]`。
- 显示投影：EPSG:3857 Web Mercator。
- 几何计算：以围墙节点平均位置为原点建立局部米制平面，先在平面中计算内外法线、宽度、转角和构件尺寸，再转回 WGS-84；没有直接给经纬度加减固定小数。
- Esri World Imagery 与 WGS-84 GeoJSON 可直接对齐，不使用 GCJ-02 或 BD-09 转换。
- 天河公园中心：`23.1304739, 113.3618998`。
- 最大拖动范围：西南 `23.075, 113.29`，东北 `23.19, 113.44`。

```js
  [23.1287381, 113.3649835],
  [23.1287381, 113.3607434],

```

主要参数：

```js
wallThicknessMeters: 1.8,
wallHeightMeters: 6.5,
topWalkwayWidthMeters: 1.2,
topGuardHeightMeters: 1.1,

```

围墙仍由真实带状 Polygon、转角平台、巡逻通道、外侧胸墙、内侧护墙、观察口和火力口组成，不是固定屏幕像素线。

## 施工走廊

全局基准保存在 `js/environment-config.js`：

```js
foundationWidthMeters: 3.2,
innerServiceRoadWidthMeters: 4.5,
outerClearZoneWidthMeters: 8,
vegetationTransitionWidthMeters: 3,
drainageWidthMeters: 0.35
```

每一环境段可覆盖这些基准。树林段的外侧清理带扩大到 9.5 米，门区扩大到 12 米；湖岸段为 5 米并使用 3.8 米维护路；水面短跨段不铺土路，而使用较厚连续混凝土基础、块石护岸和三道低矮涵洞/导流构件。地基宽 3.2 米，内侧维护路通常宽 4.5 米。

地表由数层实际面积多边形组成：

1. 不透明施工走廊底层，负责遮住与工程冲突的原树冠和地表。
2. 外侧清理带和内外植被过渡带，边缘按米制采样后加入小幅确定性起伏。
3. 压实土、浅土、碎石和车辙斑块，避免整圈成为单一纯色。
4. 3.2 米钢筋混凝土地基、墙脚接触阴影、0.35 米排水沟。
5. 内侧连续维护路、转角扩宽基础、门区混凝土前坪。
6. 湖岸块石和加厚基础，水面短跨段的连续基础与导流构件。
7. 近景才出现的少量树桩、防撞桩等低面数构件。

这里的“不规则”来自地理几何边缘的米制扰动，不是 CSS 阴影或屏幕像素描边。

## 门区、湖岸与坡地

- 西侧主车辆门：第 8 条原始边的 43.5% 位置，门宽 6.8 米，15 米深混凝土缓冲前坪。
- 南侧维护门：第 6 条原始边的 46% 位置，门宽 4.8 米，11 米深前坪。
- 门体是贴合外墙面的低面数深灰钢制挤出体，近景显示门区防撞桩。
- 湖岸段使用较宽块石护坡和加厚混凝土基座；水面短跨段不铺棕色土路，并保留低矮导流构件。
- 坡地段使用分段低台阶基础覆盖，避免把全部施工带表现成完全平滑的单色带。

当前底图不提供可供客户端读取的地形高程，所以页面不能声称已按真实 DEM 精确贴坡。现阶段采用局部分段台阶和挡土基础表达高差；若以后接入合法 DEM，可把每段底高程改为真实采样值。

## 细节层级与性能

- 14 级：整体墙体、不透明重建走廊、主要地基和清理范围。
- 14.5—15 级：维护道路、材质变化、湖岸加固。
- 15.5—16.25 级：门体、前坪、坡地台阶和排水。
- 17.25 级以上：少量树桩、防撞桩、观察口和墙面细节。

小构件数量受控，远景不会一次渲染全部细杆和近景构件。地图仍支持拖动、滚轮和双指缩放、旋转及倾斜；左上角 `3D` 与 `俯`按钮用于切换倾斜视角和北向俯视。

## 隐藏编辑模式

正常地址：

<https://zanmdmw-bit.github.io/shelter-map/>

环境与围墙编辑地址：

<https://zanmdmw-bit.github.io/shelter-map/?editWall=1>

编辑模式提供：

- 8 个可拖动围墙节点、增加节点、删除节点。
- 围墙中心线，以及地基、维护路、清理带、植被过渡边界辅助线。
- 17 个环境段下拉选择。
- 单段类型切换：树林、草地、湖岸、水面短跨、道路门区、坡地、城市边缘。
- 单段外侧清理宽度调整。
- 单段维护路、排水、岸坡加固、台阶基础开关。
- 坐标、GeoJSON、环境配置和完整配置导出。

浏览器内编辑不会写入 GitHub。确认结果后，需要把围墙节点写回 `wall-config.js`，把环境段写回 `environment-config.js`，再提交部署。正常地址不创建节点、标签、红线或其他开发辅助层。

## 文件结构

```text
shelter-map/
├── index.html
├── css/
│   └── map.css
├── js/
│   ├── bootstrap.js
│   ├── map.js
│   ├── wall-config.js
│   ├── wall-geometry.js
│   ├── wall-renderer.js
│   ├── wall-editor.js
│   ├── environment-config.js
│   ├── environment-geometry.js
│   └── environment-renderer.js
└── README.md
```

- `environment-config.js`：17 个人工环境段、真实米制宽度、两处门区和材质参数。
- `environment-geometry.js`：局部米制偏移、施工走廊、道路、清理带、湖岸、坡地与门区几何。
- `environment-renderer.js`：不透明地表覆盖、材质分层、三维低结构和缩放级别控制。
- `wall-editor.js`：仅在 `editWall=1` 时启用节点和环境分段调整、配置导出。

全部资源使用相对路径，适用于 GitHub Pages 的 `/shelter-map/` 子目录。
